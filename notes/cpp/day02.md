# Day02 - C++ 对象生命周期与 RAII

> 学习日期：2026-07-07

## 今日学习内容

今天主要学习了 C++ 对象生命周期（Object Lifetime）以及 RAII（Resource Acquisition Is Initialization）思想，这是现代 C++ 和存储系统开发的重要基础。

### 1. 对象生命周期

学习了一个对象从创建到销毁所经历的完整过程：

```text
申请内存
    ↓
调用构造函数
    ↓
对象进入可使用状态
    ↓
对象离开作用域
    ↓
调用析构函数
    ↓
释放内存
```

理解了对象必须先拥有内存，构造函数才能完成初始化；析构函数则需要在对象内存释放之前执行，以便正确释放对象所管理的资源。

---

### 2. 栈对象与堆对象

学习了两种对象创建方式：

栈对象：

```cpp
File file;
```

特点：

* 生命周期由作用域控制
* 离开作用域自动调用析构函数
* 不需要程序员手动释放

堆对象：

```cpp
File* file = new File();
```

特点：

* 生命周期由程序员控制
* 必须调用 `delete`
* 忘记释放会造成内存泄漏

理解到：**堆对象的生命周期不是由函数结束决定，而是由 `delete` 决定。**

---

### 3. RAII 思想

理解了 RAII 的核心思想：

> 在构造函数中获取资源，在析构函数中释放资源。

这样即使程序发生异常、提前返回，也能够保证资源被正确释放。

典型资源包括：

* 文件句柄
* 内存
* 锁（Mutex）
* Buffer
* Socket

---

### 4. RAII 与存储系统

认识到数据库和存储系统中大量资源都遵循同一种生命周期：

```text
获取资源
    ↓
使用资源
    ↓
释放资源
```

RAII 利用对象生命周期自动完成资源释放，大大降低了资源泄漏和异常处理带来的风险。

---

### 5. Owner（资源拥有者）

今天建立了一个重要的软件设计思想：

> **谁拥有资源，谁负责管理资源的整个生命周期。**

例如：

```text
Database
├── WAL
├── BufferPool
└── Cache
```

`Database` 是这些资源的拥有者，因此负责它们的创建和销毁，而不是让各个模块互相管理。

这是现代 C++ 和存储系统设计中的重要原则。

## 今日收获

今天最大的收获不是掌握了语法，而是理解了现代 C++ 的资源管理思想。

对象不仅仅是一块内存，更代表着一个资源生命周期。构造函数负责初始化资源，析构函数负责释放资源，这使得 C++ 能够天然地管理文件、锁、内存等系统资源，也解释了为什么现代数据库和存储系统大量采用 RAII 设计。

# Day 3 学习总结——对象组合与生命周期

## 今日学习内容

### 1. 对象生命周期

学习了 C++ 对象完整的生命周期：

> 申请内存 → 成员对象构造 → 构造函数执行 → 对象创建成功 → 析构函数执行 → 成员对象析构 → 内存释放

进一步理解了：**对象只有在构造函数执行完成后，才算真正创建成功。**

---

### 2. 对象组合（Composition）

学习了一个对象内部包含多个成员对象时的构造与析构顺序。

例如：

```cpp
class Database {
    Logger logger;
    Buffer buffer;
    File file;
};
```

掌握了两条重要规则：

* 成员对象按照**声明顺序**构造。
* 成员对象按照**相反顺序**析构。

这是 C++ 语言保证的规则，与构造函数初始化列表中的书写顺序无关。

---

### 3. RAII 思想

进一步理解了 RAII（Resource Acquisition Is Initialization）的思想：

* 资源在对象构造时获取；
* 资源在对象析构时自动释放；
* 对象生命周期与资源生命周期保持一致。

RAII 能有效避免：

* 内存泄漏
* 文件未关闭
* 锁未释放
* 异常导致资源泄漏等问题

---

### 4. 工程思维

站在存储系统角度思考了对象设计：

* Logger 为什么通常最先构造、最后析构；
* File 为什么必须比 Buffer 活得更久；
* 为什么数据库更倾向于使用对象组合，而不是大量使用裸指针；
* 为什么锁对象需要依赖 RAII 自动释放。

## 今日收获

今天最大的收获不是学会了构造函数和析构函数，而是理解了一个更重要的思想：

> **对象不仅保存数据，更重要的是管理资源。**

以后看到一个类时，应该首先思考：

1. 它拥有哪些资源？
2. 谁负责管理这些资源？
3. 生命周期应该如何设计？
4. 是否满足 RAII 思想？

这也是现代 C++ 和存储系统设计的重要基础。

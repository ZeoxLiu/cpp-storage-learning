# Day 4 学习总结——拷贝构造与资源所有权

## 今日学习内容

### 1. 拷贝构造函数

学习了拷贝构造函数的定义：

```cpp
ClassName(const ClassName& other);
```

理解了：

> 使用一个已经存在的对象创建一个新的对象时，会调用拷贝构造函数。

常见调用场景：

* 对象初始化
* 值传递
* （理论上）函数返回对象

---

### 2. 浅拷贝

理解了编译器默认生成的拷贝构造属于浅拷贝。

浅拷贝会逐个复制成员变量。

例如：

```cpp
file1.fd = 5;
file2.fd = 5;
```

复制后，两个对象保存的是同一个文件描述符，而不是两个独立的文件。

---

### 3. 为什么资源对象不能随便拷贝

如果资源对象发生浅拷贝，就可能导致：

* 同一个文件被关闭两次（Double Close）
* 同一块内存释放两次（Double Free）
* 同一把锁释放两次（Double Unlock）

这些都会导致程序错误甚至崩溃。

因此，管理资源的对象不能直接使用默认拷贝。

---

### 4. RAII 与资源所有权

今天进一步理解了 RAII 的核心思想：

> **资源必须有明确的拥有者（Ownership）。**

一个资源只能由一个对象负责管理，不能让多个对象同时认为自己拥有同一份资源。

现代 C++ 对资源对象通常采用三种策略：

* 禁止拷贝（`= delete`）
* 深拷贝（重新申请资源）
* 转移所有权（Move）

---

### 5. 工程思维

通过 BufferPool、File、Mutex 等例子，理解了为什么数据库源码中大量出现：

```cpp
ClassName(const ClassName&) = delete;
```

因为这些类管理的重要资源，不适合默认复制。

## 今日收获

今天最大的收获是理解了：

> **拷贝的不只是数据，更可能是资源的所有权。**

以后设计一个类时，需要首先判断：

1. 这个类是否拥有资源？
2. 是否应该允许拷贝？
3. 如果允许拷贝，是浅拷贝、深拷贝还是移动？
4. 如何保证 RAII 不被破坏？

这一思想不仅适用于文件对象，也适用于锁、Socket、数据库连接、BufferPool 等所有资源管理类，为后续学习智能指针、移动语义和存储系统设计打下了基础。
